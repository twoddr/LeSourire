Le Sourire — installation rapide (Linux / macOS)
================================================

Prérequis
---------
- MariaDB (ou MySQL) installé et démarré sur le PC serveur du cabinet.
- Première install : exécutez une fois sql/01_creer_bd.sql
  (mysql -u root -p < sql/01_creer_bd.sql).
- Ce dossier contient une JRE Java 21 :
  - Linux : jre-linux/
  - macOS : jre-mac/
  Les scripts détectent l'OS tout seuls.
  Si le dossier jre-* est vide, copiez-y une JRE 21 (voir JRE-A-COPIER.txt).

Premier démarrage (PC principal / serveur)
------------------------------------------
1. Ouvrez serveur/lesourire-serveur.conf.sh et vérifiez :
   - URL MariaDB (défaut jdbc:mariadb://localhost:3306/lesourire)
   - utilisateur / mot de passe (défaut admin / csa-soft)
   - port Le Sourire (défaut 8420)

2. Dans un terminal, depuis ce dossier :
     ./1-Demarrer-Serveur.sh
   Le serveur affiche ses logs dans le terminal et les écrit dans
   serveur/logs/lesourire-serveur.log (Ctrl+C pour arrêter).
   Pour un lancement masqué, utilisez plutôt ./ToutDemarrer.sh.

3. Dans un autre terminal :
     ./2-Demarrer-LeSourire.sh
   Connexion : admin / admin
   Adresse serveur = http://localhost:8420
   (ou http://ADRESSE-DU-PC:8420 depuis un autre poste).

Un seul PC
----------
Vous pouvez utiliser ./ToutDemarrer.sh :
cela lance le serveur en arrière-plan, affiche un indicateur pendant
l'attente, puis lance le client — uniquement lorsque le serveur est prêt
(même si le premier démarrage, migrations comprises, prend du temps).
Arrêtez le serveur avec ./Arreter-Serveur.sh.
La détection du démarrage utilise « curl » (ou « nc » à défaut) :
installez « curl » si aucun des deux n'est présent.

Postes clients supplémentaires
------------------------------
- Copiez seulement le dossier client + jre-linux (ou jre-mac)
  + 2-Demarrer-LeSourire.sh (ou tout le dossier lesourire-mac-linux).
- Dans l’écran de connexion, ouvrez « Adresse du serveur » :
  http://192.168.1.10:8420

Mise à jour (ne jamais remplacer que les .jar)
----------------------------------------------
1. Arrêtez le serveur : ./Arreter-Serveur.sh
2. Sauvegardez la base (le module Sauvegardes du client, ou mysqldump) et
   vérifiez que « fichiers/cle-chiffrement.key » est bien présent.
3. Décompressez le nouveau paquet dans un dossier hors « Program Files » et
   hors OneDrive, puis recopiez votre configuration :
   serveur/lesourire-serveur.conf.sh (URL MariaDB, identifiants, port).
4. Conservez telles quelles :
   - « fichiers/cle-chiffrement.key » : la clé qui relit les données déjà
     chiffrées. NE LA REMPLACEZ JAMAIS par celle d'un autre paquet ;
   - le dossier « sauvegardes/ » (et « serveur/sauvegardes/ » des anciennes
     versions).
5. Relancez : ./1-Demarrer-Serveur.sh
   Flyway applique les migrations manquantes. Le serveur refuse de démarrer si
   la clé ne peut pas relire les données existantes : c'est voulu, cela évite
   d'écrire des données définitivement illisibles.

Outils de dépannage (livrés avec le paquet)
-------------------------------------------
- ./ToutDemarrer.sh : démarre le serveur en arrière-plan, puis le client.
- ./Lancer-Serveur-Debug.sh : démarre le serveur dans un TERMINAL visible ; tout
  s'affiche et le message d'erreur reste affiché. À utiliser dès qu'un démarrage
  échoue, au lieu de chercher dans le journal.
- ./Sauvegarder-Base.sh : sauvegarde la base (.sql) ET la clé de chiffrement,
  sans passer par le client. Ces deux fichiers vont toujours ensemble.
- ./Diagnostic-Chiffrement.sh : inventorie les clés de chiffrement du poste et
  vérifie que les données sont relisibles (rapport DIAGNOSTIC-CHIFFREMENT.txt).
- ./Arreter-Serveur.sh : arrête le serveur lancé en arrière-plan.

Au lancement, 1-Demarrer-Serveur.sh affiche le dossier utilisé, la VERSION du
paquet et l'empreinte de la clé : vous savez toujours quelle installation tourne.
Le chemin exact du dossier des sauvegardes est écrit au démarrage dans
serveur/logs/lesourire-serveur.log (ligne « Sauvegardes : dossier … »).

Chiffrement des données sensibles
---------------------------------
Les identités et données médicales sont chiffrées en base (AES-256-GCM). La clé
vit dans « fichiers/cle-chiffrement.key » et DOIT être sauvegardée avec la base :
sans elle, les données sont définitivement illisibles (une sauvegarde de la base
seule ne suffit pas). Le dossier « fichiers/ » ne doit jamais être supprimé, ni
laissé derrière lors d'un changement de dossier.

En cas de doute (erreurs sur les listes, serveur qui refuse de démarrer,
réinstallation), lancez l'outil de secours :
    ./Diagnostic-Chiffrement.sh
Il écrit DIAGNOSTIC-CHIFFREMENT.txt : clés trouvées sur la machine (empreintes),
compatibilité de chaque colonne, et la marche à suivre. Il ne modifie rien tant
que vous ne demandez pas « --rechiffrer ... --je-confirme ».

Dépannage
---------
- « Le serveur n'est pas lancé » : vérifier que le serveur tourne
  (./Arreter-Serveur.sh vous indique son état), que le pare-feu autorise
  le port 8420, et consulter serveur/logs/lesourire-serveur.log.
- « Java Runtime introuvable » : dossier jre-linux ou jre-mac manquant.
- Erreur BD : MariaDB démarré ? Identifiants dans lesourire-serveur.conf.sh ?
  Script sql/01_creer_bd.sql exécuté (créé aussi l’utilisateur lesourire@localhost) ?
